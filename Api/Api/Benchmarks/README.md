# Тесты бенчмарка

Каждый подкаталог — один тест. Каталог содержит:

- `case.json` — описание теста и список известных (эталонных) ошибок;
- исходный файл, указанный в поле `entryFile` (например, `report.tex`);
- при необходимости — дополнительные файлы, подключаемые из точки входа
  (`\include{...}` для LaTeX) и изображения.

Каталог копируется в выходные файлы приложения (элемент `Content` в `Api/Api/Api.csproj`)
и читается во время выполнения. Путь можно переопределить ключом `Benchmarks.DataPath`.

## Формат `case.json`

```json
{
  "id": "orthography-basics",
  "name": "Базовая орфография",
  "description": "Необязательное описание",
  "format": "Latex",
  "entryFile": "report.tex",
  "displayMode": "Always",
  "expected": [
    {
      "number": 1,
      "chapter": "<root>//Введение",
      "line": 2,
      "title": "Краткий заголовок ошибки",
      "comment": "Подробное описание ошибки",
      "priority": 2,
      "class": "Орфография",
      "checkFix": true,
      "patch": [
        { "number": 2, "content": "Исправленная строка", "type": "Modify" }
      ]
    }
  ]
}
```

### Поля теста

| Поле          | Обязательное | Описание                                                                  |
|---------------|--------------|---------------------------------------------------------------------------|
| `id`          | нет          | Идентификатор теста; по умолчанию — имя каталога                           |
| `name`        | нет          | Отображаемое имя; по умолчанию равно `id`                                  |
| `description` | нет          | Произвольное описание                                                      |
| `format`      | да           | Ключ провайдера формата: `Latex`, `Pdf`, `Docx`                            |
| `entryFile`   | да           | Файл-точка входа относительно каталога теста                               |
| `displayMode` | нет          | `Always`, `Collapsed` (по умолчанию) или `Hidden` — режим показа на фронте  |
| `expected`    | да           | Список известных ошибок; должен быть непустым                              |

`displayMode` влияет только на отображение на фронте. `Hidden` означает, что тест запускается
через API, но не показывается в пользовательском интерфейсе.

### Поля известной ошибки

| Поле       | Обязательное | Описание                                                                     |
|------------|--------------|------------------------------------------------------------------------------|
| `number`   | да           | Уникальный номер ошибки внутри теста                                          |
| `chapter`  | да           | Имя главы, как его возвращает провайдер формата                                |
| `line`     | нет          | Номер строки внутри главы (с единицы)                                         |
| `title`    | да           | Краткий заголовок ошибки                                                      |
| `comment`  | да           | Подробное описание                                                            |
| `priority` | нет          | Приоритет, по умолчанию `1`                                                   |
| `class`    | нет          | Класс ошибки (орфография, пунктуация, математика и т. п.)                     |
| `checkFix` | нет          | Сравнивать ли предложенное моделью исправление с эталонным (по умолчанию `false`) |
| `patch`    | нет          | Эталонное исправление; нужно, если `checkFix` равно `true`                    |

Строки `patch` используют ту же схему, что и ответ модели: `Add`, `Delete` или `Modify`.
Номер строки — номер внутри главы (с единицы).

Несколько ошибок в одной строке описываются несколькими строками `patch` с одинаковым номером.
Для одной строки допустима одна строка `Modify` и любое количество строк `Add`.
Если для строки задан только `Add`, исходная строка остается, а новые строки добавляются после неё.
Если задан `Modify`, строка заменяется содержимым `Modify`.
Если задан `Delete`, строка удаляется.

## Как узнать правильные имена глав и номера строк

Номера строк считаются **внутри главы**, с единицы, включая пустые строки, и не совпадают
с номерами строк в исходном файле. Имя главы зависит от команды: `\chapter` образует главу
верхнего уровня («Введение»), а `\section` — вложенную с корневым префиксом
(«`<root>//Введение`»). Проще всего получить точные значения так:

1. запустить тест (`POST /api/v1/benchmarks/runs`) и посмотреть, какие строки вернула модель;
2. либо временно добавить диагностический тест, который печатает разбор главы —
   `new LatexFormatProvider(configuration).GetChaptersAsync(archive)` и
   `new DifferenceService().GetDifference(chapter, null)`, где `Difference[i].Number` — номер строки.

Согласованность тестовых данных проверяется автоматически:
[`BenchmarkCaseDataTests`](../../Application.Tests/Services/BenchmarkCaseDataTests.cs) сверяет
каждую известную ошибку с реальным разбором исходника и падает, если глава не найдена,
строка выходит за границы или указывает на пустую строку (признак сдвига нумерации).

## Ошибки в описании теста

Тест, который не удалось загрузить (некорректный JSON, неизвестный формат, отсутствующий
`entryFile`, повторяющиеся номера ошибок и т. п.), не приводит к падению приложения. Он попадает
в `GET /api/v1/benchmarks/cases` с заполненным полем `validationError`, и попытка запустить его
возвращает `400 Bad Request`.

## Правила сопоставления

Сначала найденные ошибки сопоставляются с известными детерминированно:

1. совпадение главы и номера строки;
2. совпадение главы, разница строк не больше `Benchmarks.LineTolerance` (по умолчанию `3`)
   и похожесть заголовков не ниже `Benchmarks.TitleSimilarityThreshold` (по умолчанию `0.6`);
3. совпадение главы и похожесть заголовков не ниже порога.

Сопоставление жадное: пары выбираются по убыванию оценки, каждая известная и каждая найденная
ошибка участвует не более чем в одной паре.

Оставшиеся ошибки передаются модели одним запросом (если включён `Benchmarks.LlmMatching`),
принимаются пары с уверенностью не ниже `Benchmarks.LlmConfidenceThreshold` (по умолчанию `60`).
Для сопоставления используется та же тестируемая модель.
